# 🛡️ StreamControl Architecture: Zero-Trust Perimeter & KMS Encryption

## Executive Summary & Division of Responsibilities

This implementation establishes a military-grade **Zero Trust** architecture using 100% open-source software, completely isolating internal application services (Next.js, NestJS, PostgreSQL, Redis, Evolution API) behind a hardened perimeter ring and encrypting sensitive streaming inventory credentials at rest using HashiCorp Vault.

## 2. Phase 1: Local Preparation & Perimeter Ring (DevOps Lead)

> **Zero Application Code Changes:** Phase 1 operates purely in the infrastructure and container layer.

### Step 1.1: Directory & Artifact Layout
All deployment files reside in `/infra`:
- `docker-compose.security.yml`
- `caddy/` (Custom Dockerfile with Coraza WAF & OWASP CRS)
- `authelia/` (MFA configuration with TOTP & Redis session storage)
- `crowdsec/` (Log acquisition configuration)
- `prometheus/` & `grafana/` (Observability configurations)
- `vault/` (Vault server config and transit initialization script)

### Step 1.2: Launch Local Environment
```bash
cd infra
cp .env.example .env
docker compose -f docker-compose.security.yml up -d --build
```

## 3. Phase 2: Local Routing Tests via Hosts File

To test Caddy, Coraza WAF, and Authelia MFA locally without registered public domains:

### Step 2.1: Add Local Domain Entries
- **Windows:** Edit `C:\Windows\System32\drivers\etc\hosts` (as Administrator)
- **Linux/macOS:** Edit `/etc/hosts` (with `sudo`)

```text
127.0.0.1 midominio.local
127.0.0.1 auth.midominio.local
127.0.0.1 grafana.midominio.local
```

### Step 2.2: Test Verification Matrix
1. **Public Site:** Open `https://midominio.local` (Bypasses Authelia, served via Caddy with local TLS).
2. **WAF Protection Test:** Send a simulated SQL injection probe:
   ```bash
   curl -k "https://midominio.local/catalogo?id=1'%20OR%20'1'='1"
   ```
   *Expected result:* HTTP 403 Forbidden generated by Coraza WAF before reaching Next.js.
3. **MFA Redirection Test:** Navigate to `https://midominio.local/admin` or `https://grafana.midominio.local`.
   *Expected result:* Instant 302 redirect to `https://auth.midominio.local`, prompting for username (`admin`), password (`AdminSecurity2025!`), and Google Authenticator TOTP token.

## 4. Phase 3: VPS Provisioning & Host Hardening (DevOps Lead)

### Step 3.1: LUKS Full-Disk Encryption at OS Level
When provisioning the Ubuntu/Debian VPS, ensure full disk encryption is initialized so the hosting provider cannot read raw block devices or databases:

```bash
# Format secondary disk or partition with LUKS AES-XTS-PLAIN64
cryptsetup luksFormat --type luks2 --cipher aes-xts-plain64 --key-size 512 /dev/sdb

# Open encrypted container
cryptsetup open /dev/sdb encrypted_storage

# Format and mount filesystem for docker data
mkfs.ext4 /dev/mapper/encrypted_storage
mkdir -p /var/lib/docker
mount /dev/mapper/encrypted_storage /var/lib/docker
```

## 5. Phase 4: Host-Level CrowdSec & Firewall Installation

Install CrowdSec directly on the VPS host operating system (not inside Docker) so that it controls physical kernel `iptables` and drops packets at the network layer:

```bash
# 1. Install CrowdSec Host Engine
curl -s https://packagecloud.io/install/repositories/crowdsecurity/crowdsec/script.deb.sh | sudo bash
sudo apt update && sudo apt install -y crowdsec

# 2. Install Netfilter/IPTables Bouncer on Host
sudo apt install -y crowdsec-firewall-bouncer-iptables

# 3. Connect Host CrowdSec to Caddy Container Logs
# Point /etc/crowdsec/acquis.yaml to docker volume logs:
sudo tee -a /etc/crowdsec/acquis.yaml <<EOF
filenames:
  - /var/lib/docker/volumes/streamcontrol_caddy_logs/_data/*.log
labels:
  type: caddy
EOF

sudo systemctl restart crowdsec
sudo systemctl restart crowdsec-firewall-bouncer-iptables
```

## 6. Phase 5: Production Deployment & Let's Encrypt TLS

1. Clone repository to `/opt/streaming-platform` on VPS.
2. Point DNS records (`A` record for `midominio.com`, `auth.midominio.com`, `grafana.midominio.com`) to the VPS IP.
3. Update `infra/.env` with production domain:
   ```env
   DOMAIN=tudominio.com
   ```
4. Start production stack:
   ```bash
   docker compose -f docker-compose.security.yml up -d
   ```
   Caddy will automatically provision trusted Let's Encrypt certificates via ACME TLS-ALPN-01 within seconds.

## 7. Phase 6: Inventory KMS Encryption (Backend Security Lead)

### Integration Summary
- Implemented in [`backend/src/common/vault/vault.service.ts`](file:///d:/streaming-platform/backend/src/common/vault/vault.service.ts) and [`backend/src/prisma/prisma.service.ts`](file:///d:/streaming-platform/backend/src/prisma/prisma.service.ts).
- Intercepts all read and write queries to the `Account` model.
- Streaming credentials (`passwordCuenta`, `pinPerfil`) are encrypted with AES-256-GCM before writing to PostgreSQL.
- Stored values in PostgreSQL take the form: `vault:v1:sOmECiPhErTeXt...`.
- Query results are decrypted on-the-fly when read by authorized backend services.
- **Zero impact on business logic, controllers, DTOs, or the frontend.**
